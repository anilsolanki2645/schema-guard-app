Product Overview

Schema Guard is a continuous database schema gatekeeper and data contract compliance platform. It bridges the gap between transactional application databases and downstream data consumers (dbt models, Apache Airflow ETL, Kafka stream processors, dashboards, and ML features) to prevent silent, breaking schema mutations from reaching production.

💥 The Problem

App developers alter a database table (e.g. rename user_id to customer_uuid or alter a column type from INTEGER to VARCHAR). Downstream analytics and data pipelines break silently at 3 AM.

🛡️ The Solution

Schema Guard enforces strict, version-controlled YAML data contracts locked with cryptographic SHA-256 signatures. It evaluates proposed schema changes inside CI/CD pull requests and blocks breaking migrations before merge.

⚙️

How Schema Guard Works

Schema Guard functions through a 4-phase automated lifecycle that keeps your live databases, CI/CD pull requests, and scheduled data extraction jobs completely synchronized and validated:

[Developer Pull Request / DDL] │ ▼ [CI/CD Gate: POST /api/pipelines/<id>/validate-gate] │ ├─► (1) Verify API Token & Plan Quota ├─► (2) Verify SHA-256 Contract Lock Signature ├─► (3) Diff Engine: Compare Proposed Schema vs Baseline │ ├── Checks column removals / renames │ ├── Checks type incompatibilities (e.g. TEXT -> INT) │ └── Checks nullability violations (NOT NULL shift) │ ┌─────┴────────┐ ▼ ▼ [PASS: Exit 0] [FAIL: Exit 1 (PR Blocked)] │ └── AI Diagnostic Reason & SQL Remediation Generated ▼ [Production Database] │ ▼ (Scheduled Cron Audits: Every 1m / Daily) [Multi-DB Lazy Extractor] ──► [Diff Engine] ──► [Slack / WhatsApp / Email Alerts]

1. Baseline Registration & Locking

When a pipeline is connected, Schema Guard introspects the table metadata and compiles a canonical YAML contract. The contract is cryptographically locked with a SHA-256 hash stored in both the database and file system.

2. CI/CD Gate Verification

In GitHub Actions, GitLab CI, or pre-commit hooks, developers call the gate API. Schema Guard evaluates proposed migration DDL and rejects changes that drop columns, narrow types, or break downstream consumers.

3. Automated Cron Drift Auditing

A multi-worker background scheduler queries the target database on configured cron schedules. If manual or out-of-band changes occur, immediate alerts are dispatched to Slack, WhatsApp, and Email.

4. AI Diagnostic & Repair Engine

When a schema discrepancy occurs, the integrated AI reasoning engine analyzes the structural drift, assesses the blast radius on analytics pipelines, and outputs executable SQL repair scripts.

Cryptographic Data Contracts

Data contracts are declarative, human-readable specifications written in YAML. To prevent unauthorized modifications, each contract is locked with a cryptographic SHA-256 digest:

Example: contracts/production_orders.yaml
source:
  name: production_orders_contract
  type: postgres
  connection: postgresql://readonly@db.internal:5432/analytics
  schema: public
  table: orders
columns:
  - name: order_id
    type: INTEGER
    nullable: false
    primary_key: true
  - name: customer_id
    type: INTEGER
    nullable: false
  - name: total_amount
    type: NUMERIC(12, 2)
    nullable: true
  - name: status
    type: VARCHAR(50)
    nullable: false
  - name: created_at
    type: TIMESTAMP
    nullable: false

Multi-Database Connectors

Schema Guard uses on-demand lazy extractors. Instead of holding persistent connection pools that consume database server capacity, extractors connect, inspect the database catalog metadata, and disconnect immediately.

MySQL / MariaDB mysql+pymysql://user:pass@host:3306/db information_schema.columns

CI/CD Gatekeeper Integration

Integrate schema verification into your deployment pipeline. The gate endpoint returns HTTP 200 if the proposed migration is safe, or HTTP 422 if breaking changes are detected:

GitHub Actions Workflow (.github/workflows/schema_gate.yml)
name: Schema Guard Contract Gate

on:
  pull_request:
    branches: [main, production]

jobs:
  verify-contract:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Validate Schema Compatibility
        run: |
          RESPONSE=$(curl -s -w "%{http_code}" -o response.json -X POST \
            "https://your-domain.com/api/pipelines/orders_pipeline/validate-gate" \
            -H "Content-Type: application/json" \
            -H "X-Schema-Guard-Token: ${{ secrets.SCHEMA_GUARD_API_KEY }}" \
            -d '{
              "commit_sha": "${{ github.sha }}",
              "branch": "${{ github.ref_name }}",
              "schema": {
                "columns": [
                  {"name": "order_id", "type": "INTEGER", "nullable": false},
                  {"name": "customer_id", "type": "INTEGER", "nullable": false},
                  {"name": "total_amount", "type": "NUMERIC(12,2)", "nullable": true}
                ]
              }
            }')
          
          HTTP_STATUS=$(echo "$RESPONSE" | tail -c 4)
          cat response.json
          
          if [ "$HTTP_STATUS" -ne 200 ]; then
            echo "❌ Schema contract validation failed! Breaking changes detected."
            exit 1
          fi
          echo "✅ Schema verified compliant with locked contract."
💻 Official Standalone Schema Guard CLI (schemaguard)

Execute local pre-commit hooks, CI/CD gates, DDL lock risk assessments, and cryptographic contract locking directly from your terminal: 

# Run CI/CD Gate check (exits with code 1 on breaking drift)
python manage.py schemaguard gate --pipeline <pipeline_id> --strict

# Assess DDL lock level, table rewrite risk, and zero-downtime recipes
python manage.py schemaguard impact --ddl "ALTER TABLE orders ADD COLUMN status varchar(50);" --dialect postgres

# Verify contract baseline drift against live database
python manage.py schemaguard check --pipeline <pipeline_id> --json

# Cryptographically lock contract baseline
python manage.py schemaguard lock --pipeline <pipeline_id>

Apache Airflow Pre-Ingestion Guard

Export and drop the native SchemaGuardOperator or SchemaGuardSensor into your Airflow DAGs. It verifies that the source table structure matches the locked contract before starting long-running extraction or ETL jobs:

Airflow DAG Implementation (dags/orders_etl.py)
from datetime import datetime, timedelta
from airflow import DAG
from airflow_operator import SchemaGuardOperator

default_args = {
    'owner': 'data-engineering',
    'retries': 2,
    'retry_delay': timedelta(minutes=5),
}

with DAG(
    dag_id='production_orders_ingestion',
    default_args=default_args,
    start_date=datetime(2026, 1, 1),
    schedule_interval='@daily',
    catchup=False,
) as dag:

    # 1. Pre-Ingestion Guard: Blocks ETL if database schema mutated
    guard_orders = SchemaGuardOperator(
        task_id='guard_orders_schema',
        endpoint_url='https://your-domain.com/api/pipelines/orders_pipeline/validate-gate',
        token='{{ var.value.SCHEMA_GUARD_TOKEN }}',
    )

    # 2. Downstream tasks only execute if schema passes
    extract_orders >> transform_orders >> load_warehouse
    guard_orders >> extract_orders

Security, Encryption & RBAC

Schema Guard is engineered according to strict enterprise security standards:

  • Fernet AES-128 Encryption at Rest: Database passwords and connection strings stored in core_pipeline and core_connectionprofile are encrypted using Fernet symmetric encryption.
  • Automatic Masking: Sensitive database connection strings are masked with asterisks (postgresql://user:****@host/db) in all API responses and dashboard tables.
  • SQL Injection Sanitization: All schema, table, and column names are quoted with dialect-safe delimiters (e.g. "table" for Postgres/Snowflake, `table` for MySQL) before running data quality queries.
  • Cryptographic API Keys: API keys use an unguessable prefix (sg_live_...) and are stored exclusively as SHA-256 hashes in the database.
  • Immutable Audit Trail: Every user action (logins, pipeline creations, contract locks, API key creation/revocation, plan changes) is immutably recorded in the AuditLog table.

Complete REST API Specification

⚡ Interactive OpenAPI 3.1 Swagger Playground

Explore, test, and execute all 25+ Schema Guard API endpoints directly from your browser with live token authorization.

Open Swagger UI 🚀
POST /api/pipelines/<pipeline_id>/validate-gate

Validates a proposed schema against the locked contract baseline. Requires X-Schema-Guard-Token header.

Response: 200 OK {"compatible": true, "violations": []} or 422 Unprocessable Entity {"compatible": false, "violations": [...]}
GET /api/pipelines

Lists all monitored pipelines within the authenticated user's organization with masked credentials.

POST /api/pipelines/<pipeline_id>/run

Forces an immediate live audit check against the target database and dispatches alerts if drift is detected.

POST /api/billing/checkout

Initiates a Stripe Checkout Session for upgrading plan tier ({"plan": "pro"} or {"plan": "enterprise"}).

GET /api/health

Returns server health, database connection status, and scheduler state for load balancers.

GET /api/pipelines/<pipeline_id>/badge

Returns a shields.io-compatible dynamic SVG status badge (passing, drifted, failed) for GitHub repository READMEs.

GET /api/audit-logs/export

Exports full immutable audit trails to a downloadable CSV format for SOC2, ISO27001, and compliance audits.
